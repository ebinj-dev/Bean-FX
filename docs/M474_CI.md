# M474 CI — publication procedure (carried into M48-G)

## Current state (honest)

- **No GitHub Actions run exists.** `.github/workflows/` has never been committed to
  this repository (verified across all M47.4 commits and `origin/main`).
- The release-gate workflow is **preserved as CI-as-data** at
  `docs/ci/release-gate.yml` (added in M48-G) — complete, validated YAML with the
  four jobs the M47.4 release gate defined: `verify-lockfiles`,
  `typecheck-and-lint`, `e2e-security-and-build`, and the live-server suites.
- Publication is **BLOCKED by token scope**: the workspace OAuth token grants
  `repo` only. GitHub rejects any push that creates/updates
  `.github/workflows/*` without the `workflow` scope. M47.4 recorded the same
  blocker (see `docs/M474_RELEASE_GATE.md` item 9). This was re-verified in
  M48-G by reading the token's `X-OAuth-Scopes` header from the GitHub API.

## Owner activation (one re-auth + one move)

1. Re-authenticate the device-flow token with BOTH `repo` and `workflow`
   scopes (procedure in `GITHUB_AUTH.md`). No secret ever enters chat: the
   device flow stores the token locally, as before.
2. On a branch:
   ```bash
   mkdir -p .github/workflows
   git mv docs/ci/release-gate.yml .github/workflows/release-gate.yml
   git commit -m "M474 CI: activate the release gate (workflow scope granted)"
   ```
   Push the branch and open a PR; the first Actions run appears on the PR.
3. Protect `main` (Settings → Branches → Add rule):
   - Require a pull request before merging.
   - Require status checks: `verify-lockfiles`, `typecheck-and-lint`,
     `e2e-security-and-build`.
   - Require branches to be up to date before merging.
