# M14 — AI Art Direction & Motion Composition

M14 turns BEAN FX into a narration-aware visual storytelling system: an AI Motion Art Director proposes (never applies) three distinct creative directions; a deterministic scene composer plans scenes from RIISHE's VERBATIM timestamps with AI concept suggestions; LAXII generates style-consistent scene assets under the approved direction; a REAL layered compositing engine (canonical evaluator → deterministic PIL compositor → FFmpeg) renders compositions through the existing durable worker; NIIKI-family motion presets animate layers with M13 tracking bindings following the established gap policy. Reference principles (bang-motion, vox-director, huashu-art-motion, claude-drawing-skill) were adopted as **inspiration only** — see `docs/M14_REFERENCE_AUDIT.md` for the licensing review. **M15 was not started; M1–M13 remain untouched (full matrix green).**

## 2. Art direction (§4)
`generateDirections()` builds a structured prompt from the brief (project context, story/product, audience, format, narration, brand references, style hint, motion intensity, EN/TA) and validates `{"directions":[exactly 3]}` via `ArtDirectionSetSchema`. Each direction: name, rationale, style profile (palette with **per-swatch provenance** `direction|system|user-brand`, medium, texture, line treatment, lighting, composition, shape language, consistency rules), typography, background treatment, illustration approach, composition approach, motion language, scene continuity, asset requirements, transitions, constraints (including the honesty rule that independent generations do NOT guarantee identical character identity). A deterministic **anti-homogenization fingerprint** (FNV over name+medium+composition+palette) distinguishes proposals. Directions persist as `ArtDirection` rows (`PROPOSED → APPROVED/DISCARDED`); sibling candidates stay comparable; approval gates asset generation (refusal without an approved direction). Edit/regenerate/compare operate per row — approved material is never overwritten.

## 3. Scene composer (§5)
`segmentScenes()` is DETERMINISTIC: transcript segments (M11 measured context) group into scenes of ~2–3 segments; `startSec/endSec` are **RIISHE-verbatim** (`timingSource: "riishe-verbatim"`, evidence lists the segment refs). Without a transcript, estimated slots are flagged `timingSource: "estimated"` with explicit ESTIMATE labels. AI enrichment (`SceneConceptSetSchema`) adds visual concept/composition/on-screen text/motion/camera/transition per scene — **timings are fixed input, never output**; on-screen text is stored whole (Tamil-safe; no code-point slicing). Edits: manual reorder (full-list validation), duration overrides (verbatim scenes re-labelled `estimated` + `REVISED` with the original RIISHE ref preserved), per-scene approval; `regenerateScene` regenerates ONE scene's creative fields and leaves approved scenes untouched. `validateContiguity` reports gaps/overlaps as deliberate-pending-approval rather than silently fixing them. Scene plans persist as `ScenePlan` rows (versioned by edit).

## 4. LAXII asset studio (§6)
`generateSceneAsset()` refuses without an APPROVED direction; prompts are built from the direction's style profile (`styleProfilePromptBlock`) + scene role/concept; size maps from the plan's format (16:9→1344x768 etc. — the provider's verified size list); alternatives (1–3) generate sequentially. Every asset registers through the existing lifecycle (stable ID, provider/label, prompt, params incl. direction fingerprint, license/attribution). **Alpha honesty**: `verifyAlpha()` reads ACTUAL pixels via PIL (`RGBA` histogram coverage) — the live run reports `alpha=false` with the explicit limitation "transparency is NOT claimed for this asset" (the provider returns opaque JPEG bytes, as first verified in M7). Failed registrations clean up temp files in `finally`. Non-destructive: original generated assets are preserved; comparisons/regeneration create NEW registrations.

## 5. Motion presets (§7)
Nine deterministic preset generators (`soft-reveal`, `cinematic-push-in`, `floating-movement`, `bounce-entrance`, `kinetic-typography`, `scene-transition`, `parallax-drift`, `track-following-graphic`, `emphasis-pulse` — beat-aware via RIISHE beat frames) produce integer-frame `LayerKeyframe`s (stable IDs `m14<preset><prop><frame>`) in the NIIKI interpolation family; determinism is test-proven (byte-identical output). `evalKeyframes()` mirrors the evaluator (`EASE_OUT` at u=0.5 → 0.875 spot-checked against `easeProgress`). Presets RETURN keyframes — the caller commits them through composition versioning (reversible, undoable).

## 6. Compositing foundation (§8) — real rendering, not a mockup
**One canonical representation** (`CompositionDoc`: canvas + ≤24 layers of kind background/image/video/graphic/text/shape with transform, anchor, blend, frame range, keyframes, alpha mask, M13 binding) evaluated by **one deterministic evaluator** `evaluateCompositionAt()` → per-frame `CompositionFrameState` (visibility, opacity-clamped, transforms, resolved track position + honest gap flag). **Both preview and export consume this evaluator's state** — parity by construction:
- **Export**: `COMPOSITION_RENDER` job (existing durable worker, 30 min timeout, per-user concurrency 1) → per-frame states (same evaluator) → **PIL compositor** (source-over with off-canvas clipping, multiply/screen RGB-space blend with documented conventions, alpha masks with invert/opacity, anchor-based transform order scale→rotate→position) → **FFmpeg encode** (x264, yuv420p) with optional audio mux from the timeline's audio asset → registered as a VIDEO asset with full provenance (layers, blend modes used, frame range, bindings).
- **Pixel evidence**: the core suite renders a composition with known math and probes the DECODED H.264 frame — multiply(red,green)=(0,0,0), screen(white,bg)=(255,255,255), bg=(32,32,32), all within the documented ±6 tolerance (JPEG+chroma subsampling).
- **Blend modes advertised**: `normal`, `multiply`, `screen` ONLY — each pixel-tested on the export path and defined in the shared evaluator contract for the preview path. Nothing else is advertised.
- **Quality gates**: `validateComposition` enforces layer/pixel/frame limits, non-finite transforms, duplicate ids, unknown mask sources, empty ranges, and an anti-PowerPoint note when NO layer moves (reported, not silently approved).
- **Resource protection (§15)**: ≤24 layers, ≤1920px, ≤3600 frames, ≤120s render wall, one frame in memory at a time (never a whole video), temp frames cleaned in `finally`, cancellation verified between frames via a cancel-flag file, progress reporting, worker recovery via the durable queue, render provenance recorded.
- **Non-destructive**: compositions are versioned documents; rendering never flattens the project.

## 7. M13 tracking-aware compositing (§9)
`attachLayerToTrack()` requires a COMPLETED M13 temporal index and a matching track/asset (honest refusals otherwise — E2E-proven). The binding stores the M13 track id, HOLD gap policy, offsets and the attached frame range. `resolveTrackBinding()` maps composition frames → source seconds (fps + offset), **holds the last VISIBLE sample** (occluded samples are never trusted), flags `trackGap` honestly, and returns the offset-adjusted normalized position in composition pixels. Detach/reattach are version commits; layers remain editable after attachment; undo restores prior binding state. CSRT tracking is never presented as identity recognition; occlusion limitations carry through the warnings.

## 10. Privacy (§3/§15)

## 12. Known limitations (honest)
- Provider image output is opaque (no alpha) — cutout/transparency is NOT claimed; real segmentation is out of scope.
- Character identity across independent generations is NOT guaranteed — stated on every character-asset generation.
- Blend modes limited to normal/multiply/screen; the documented convention blends in RGB space with source-over alpha placement.
- Preview canvas in the browser consumes the same evaluator contract; full in-browser canvas preview rendering ships as the shared state contract (parity proven on the export path; the panel shows layer state, not a live pixel canvas — future work: WebGL/canvas pixel preview).
- Scene enrichment without a provider keeps empty concept fields (manually editable) — never fabricates.
- No load testing — no capacity claims.
