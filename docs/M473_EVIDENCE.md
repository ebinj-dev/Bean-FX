## C. Dependency reproducibility — nodemailer mismatch RESOLVED

**Root cause:** the project installs with **bun** (`bun.lock` contains `nodemailer@10.6.0`), but
`package-lock.json` was never regenerated — npm's lockfile went stale. Worse, plain
`npm install`/`npm ci` cannot even regenerate it: the root declares `nodemailer@^10.6.0` while
`next-auth@4.24.15` declares `peerOptional nodemailer@^7.0.7` — npm's strict peer resolver
refuses (bun ignores optional-peer conflicts).

**Fix (npm's own mechanism, minimal):** `package.json` `"overrides": { "next-auth": { "nodemailer": "$nodemailer" } }`
+ `npm install --package-lock-only` (lockfile regenerated by npm's resolver; no manual lockfile
editing; `bun install --frozen-lockfile` still passes — bun.lock unchanged).

**Verification:**
- Isolated clean install: `npm ci` (plain, no flags) in a fresh directory → **exit 0**,
  nodemailer@10.6.1 + next-auth@4.24.15 installed.
- The regenerated lockfile ALIGNS WITH REALITY: sampled versions (@formatjs/intl-localematcher
  0.8.14, @formatjs/fast-memoize 3.1.7, sharp 0.35.5) now match the bun-installed node_modules —
  the old lockfile was stale on all of them.
- Audit regenerated on the new lockfile: **1007 lockfile entries → 584 production instances**
  (548 unique names, 37 nested) + 423 dev instances; classification 568 PERMISSIVE /
  14 COPYLEFT-WEAK / 2 NON-STANDARD; 0 unresolved licenses; SBOM 1007 components.
- **Before → after:** 995 entries / 577 prod / 418 dev → 1007 / 584 / 423.
- 16/16 audit tests (including the flipped invariant: NO declared-but-uninstalled dependencies remain).
