## B. Before EVERY push

1. `git status --porcelain` — review every modified file; nothing accidental.
2. `git diff --stat HEAD` — confirm the change set matches the task you did.
3. **Secret scan of the staged diff** (never skip):
   - `git diff --cached | grep -nEi "(sk-[A-Za-z0-9]{16,}|AKIA[A-Z0-9]{12,}|ghp_[A-Za-z0-9]{20,}|github_pat_|PRIVATE KEY|AIza[A-Za-z0-9_-]{20,}|password|secret|token)"` — investigate every hit.
   - Or run `gitleaks protect --staged` if installed.
4. Confirm `.env`, `db/`, `backups/`, `media-store/`, `upload/`, `download/`, venvs are **not** in the staged set: `git diff --cached --name-only`.
5. `bunx tsc --noEmit` and `bun test ./scripts/` — green before push.
6. **M20 durable-render LIVE GATE (mandatory before a release is qualified — M40 §5):**
   run `scripts/m20-regression-gate.sh` (or the full sequence via `scripts/release-qualify.sh`). A release must NOT be marked qualified unless the complete M20 live suite passed on the exact code being released — real standalone server, real FFmpeg, isolated scratch DB + scratch media, machine-readable evidence in `download/m20-render-logs/gate-summary.json`, exit code 0. Developer-loop iterations may skip the gate; **release qualification may not**.
   Expected qualification sequence: `BUILD → UNIT/INTEGRATION → M20 LIVE GATE → SECURITY → RELEASE QUALIFICATION`.
7. Push with `--dry-run` first: `git push --dry-run origin <branch>`.

## C. GitHub-side settings (owner action)

1. **Secret scanning** — enable in Settings → Code security (automatic on public repos; on private repos available with GitHub Advanced Security).
2. **Push protection** — enable so pushes containing detected secrets are blocked server-side.
3. Branch protection on `main` (require PR review when more collaborators join).
4. Dependabot alerts (free) for `package.json` + `requirements.txt`.
5. If a secret is ever detected in pushed history: **revoke/rotate the credential first**, then remove it from history with explicit approval (`git filter-repo` or BFG), then force-push — in that order.

## D. Never in the repository (standing rule)

`.env`, any token/key/certificate, `db/`, `backups/`, `media-store/`, `upload/`, `download/`, `.venv/`, `node_modules/`, `.next/`, model weights, logs, machine-specific config (`Caddyfile` is reviewed before publishing).
